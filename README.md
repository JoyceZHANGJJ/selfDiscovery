# 识己手札

一个记录「觉察 / 此刻 / 可做 / 待办 / 随记」的微信小程序（云开发）。

## 目录结构

## 数据模型

集合：`records` / `options` / `usercfg` / `analysis`（云开发；`analysis` 是唯一的云函数，其余读写都在小程序端直连数据库）。

一条记录 `records`：

| 字段 | 说明 |
| --- | --- |
| `m` | 模块：`obs` 觉察 / `now` 此刻 / `want` 可做 / `todo` 待办 / `jot` 随记，或自定义维度 `d…` |
| `txt` | 主项一句话（觉察是「归类」、此刻是「想记的是」、可做是「什么事」） |
| `ts` / `t` | 创建时间戳 / 显示用的时刻 |
| `ext` / `extSrc` | **细节值与其来源，按下标一一对应**（见下） |
| `done` / `doneAt` | 完成标记与完成时间 |
| `status` / `startedAt` / `abandonedAt` | 流转：可做与待办的 `doing` / `done` / `abandon` |
| `endTs` | 觉察的结束时间 |
| `dueTs` | 待办的**计划完成**时间（0＝没计划，是常态）。**放顶层而不是 ext**：ext/extSrc 是按位置对齐的两条数组，导出导入 / 迁移 / 改名都挂在这套对齐上，往里塞时间戳会让对齐变别扭。行尾那一格挂「计划完成」胶囊，**占着创建时间的位置**——有计划就显示计划、不再显示创建时间，没计划才显示创建时间（原因照常显示），右端永远只有一个日子。胶囊点一下＝取消（先问一句，见 `pageBase.clearDue`）；要定／改日子走左滑面板或记卡那一行 chips |
| `calTs` | 最后一次「推到手机日历」的时间（0＝没推过）。只作回显——小程序读不回系统日程。**改 `dueTs` 会连带清掉它**（日程带的是旧时间，留着就是假话；见 `store.setDue`） |
| `ref` / `refTxt` / `refTs` | 老数据（原「做了」模块）遗留的引用 |

**`ext` 与 `extSrc` 是按顺序对齐的两条数组**——这是细节回显、改名、迁移、导出导入的地基：
- `extSrc[i]` 说明 `ext[i]` 来自哪：选项组 key（如 `obsKind`）、`free:xxx`（自由填写）、`fx:xxx`（写死的固定组，如沉浸 / 精力）；
- 任何改字段的动作都要两条一起改（`buildExt` / `mapExtSrc` / `decorate`）；导出格式也是按这个顺序排的。

`usercfg` 按 `type` 存配置：`dims`（自定义维度）/ `greets`（问候语）/ `delDef` / `optCustom` / `optOrder`。

## 如何运行

1. 微信开发者工具打开本目录，填好 AppID。
2. 开通云开发，环境 ID 写在 `app.js` 的 `CLOUD_ENV`。
3. 建好下面那三张索引；集合若不存在，在控制台新建 `records` / `options` / `usercfg`（权限「仅创建者可读写」）。
4. 编译即可。改完代码建议先跑一遍 `python3 tools/check-syntax.py`（见下）。

## 改完自查：语法 / 配对检查

项目没有 node / eslint 的运行环境，而小程序是「**一个语法错误就整包加载失败**」（`utils/store.js` 出过一次：漏一个收尾括号 → `require` 直接抛错 → 整个小程序白屏，报错还看不懂）。
编译前先跑一遍，一秒钟的事：

```bash
python3 tools/check-syntax.py                  # 查全项目（js + wxml）
python3 tools/check-syntax.py utils/store.js pages/list/list.wxml   # 只查指定文件
```

- 只依赖 `python3`（macOS 自带），不装任何东西；**有问题时退出码为 1**，无问题为 0。
- 查两类最常见的低级事故：① js 的括号 / 引号没配对（会跳过注释、字符串、模板串、正则字面量）；② wxml 的标签没配对。
- 它不是完整解析器（不做语法树、不查语义），**真正的语法错误仍以微信开发者工具为准**；它只是把这类低级错误挡在编译之前。

## 云开发数据库索引（部署前建一次）

微信云开发的索引**只能在控制台创建，代码无法创建**。记录 / 选项变多后，缺索引会让列表分页与统计明显变慢。
请在「微信开发者工具 → 云开发 → 数据库 → 选中集合 → 索引管理」按下面建好：

| 集合 | 索引名 | 字段 | 唯一性 | 用途 |
| --- | --- | --- | --- | --- |
| `records` | `idx_ts` | `ts`（降序） | 非唯一 | 时间线倒序分页（全部 / 单维度） |
| `records` | `idx_m_ts` | `m`（升序）+ `ts`（降序） | 非唯一 | 按模块 + 时间取数（看页各维度、统计） |
| `options` | `idx_group_value` | `group`（升序）+ `value`（升序） | 非唯一 | 选项池按组读取、按值去重 |

说明：

- 三张索引都选 **非唯一**：它们只做**查询加速**，不承担业务唯一约束。`options` 集合是全用户共用的（数据按 `_openid` 隔离，但索引是全集合级），唯一索引会让不同用户添加同名选项**互相冲突**，后一个写入被拒。
- 记录按 `_openid` 隔离（云数据库默认「仅创建者可读写」），查询都带 `ts` 或 `m`，上面这些索引即可覆盖绝大多数查询。
- `ext`（细节标签）是数组，等值 / `_.all` 筛选走不到索引；若「类别 / 喜恶」成为高频筛选，建议把该值冗余成标量字段（如 `kind`）再单独建索引。
- 索引是**一次性**配置；集合新建后补建即可，不影响已有数据。刚建好时「命中次数」为 0 属正常，跑查询后会涨。

## AI 回看（日 / 周 / 月 / 年自动生成，回看页入口）

每天凌晨（中国 01:00）由云函数 `cloudfunctions/analysis` 自动跑一次，为所有用户生成到昨天为止「该生成」的回看：

- **日回看**：每天生成，回顾昨天。
- **周 / 月 / 年回看**：自动**补齐历史**——每晚往回扫最近 12 个自然周、12 个自然月、5 个自然年，凡是「还没生成过 && 期间有记录」的都会补出来，不用等到边界日；已生成的按幂等键跳过，期间没记录的不生成（不留空卡）。单次调用最多真正调大模型 15 次（`MAX_GEN_PER_RUN`），一次补不完的下一次定时接着补，不会撞 60s 超时。

**手动触发（控制台「测试」里改提交内容）**

- `{"action":"gen","type":"day","offset":1}` —— 给当前用户生成「昨天」的日回看（`offset` 需 ≥ 1，不能生成未来的回看）。
- `{"action":"gen","type":"week"}` —— 周 / 月 / 年取最近一个已完整结束的周期（不必等到周日 / 月末 / 12-31）。
- `{"action":"backfill"}` —— 给当前用户补齐历史周 / 月 / 年（最多真生成 30 条，可用 `"maxGen": 50` 放宽）。
- 直接用测试模板（不带 action）跑只会返回 `{"ok":false}` 并附提示，不会误触发批量生成。

AI 回看页（`pages/analysis`）顶部按 日 / 周 / 月 / 年 切换，卡片可展开看：值得记住 / **更深的看见**（可能没意识到的模式、需求或矛盾） / 复盘随想 / **可以试试**（2~3 条可执行建议）。提示词的定位是「像懂心理学的咨询师做复盘」：指出模式与连接、不逐字引用原话、覆盖全部维度、建议具体有方向性，不做流水账复述。回看页顶部入口只展示最新的日回看。

**部署步骤（一次性）**

1. 控制台新建集合 `analysis`，权限同样「仅创建者可读写」。
2. 去大模型厂商拿 API Key。**默认用智谱 GLM-4-Flash（[open.bigmodel.cn](https://open.bigmodel.cn)，官方承诺永久免费、中文强、OpenAI 兼容），注册后在「API 密钥管理」创建密钥即可**，不用花钱。想用别的也行：硅基流动 `cloud.siliconflow.cn`（9B 以下模型如 `Qwen/Qwen2.5-7B-Instruct` 也永久免费）、DeepSeek（百万免费额度）、通义 / 智谱付费模型等。
3. 微信开发者工具里右键 `cloudfunctions/analysis` → **上传并部署（云端安装依赖）**。上传时 `config.json` 里的 `triggers` 会在云端建好定时器，env 里已写好默认 `LLM_BASE_URL`（智谱 base）/ `LLM_MODEL`（`glm-4-flash`）。
4. **配置密钥（关键，不写进代码）**：云函数上传后，在「云开发 → 云函数 → analysis → 配置 → 环境变量」里加一条 `LLM_API_KEY = 你的key`。换厂商就改 `LLM_BASE_URL` / `LLM_MODEL`（这里填的是「接口 base」，不含 `/chat/completions`，代码会自动拼）。
5. 在云端「日志」里手动触发一次 `analysis` 验证能跑通；之后每天自动跑。

**几个实现要点**

- 定时器触发**没有用户上下文**，所以云函数先用 `aggregate().group({_id:'$_openid'})` 捞出所有有记录的用户，再逐人生成；每条 `analysis` 都带上真实 `openid`，小程序端用 `action:'list'` 调同一云函数读回（云函数有管理员权限，能跨过「仅创建者可读写」读到对应用户的那份）。
- 生成按 `openid + type + start` 幂等（旧日回看文档沿用 `openid + date`）：已生成过就跳过，定时器偶尔重跑不会叠两份；期间没有记录就不生成，不留空卡。
- 时间按**中国时区**算（`cnToday0` 把当前时刻 +8h 再取日期），定时器 `0 0 17 * * * *` 是 UTC 17:00 ＝ 中国 01:00。周回看按自然周（周一~周日）；周 / 月 / 年不再依赖「昨天恰是边界日」，每晚自动往回扫补齐历史。还没结束的周期（未来 / 进行中）一律不生成。
- 记录上限：日回看取 100 条，周 / 月 / 年取 500 条（prompt 截前 400 条），控制 token；输出要求大模型严格返回 JSON。
- 没配密钥 / 还没到第一次触发时，回看页入口会静默不显示，AI 回看页是空态，不影响其它功能。

**排错**

- **刚「上传并部署」完，测试就报 `ret=-3 [UPSTREAM] system error`**：这是云端重建实例时的**瞬时错误**，不是代码问题。等 **1~2 分钟**再点一次「运行测试」即可；若还报，重新「上传并部署」一次，再等一两分钟重试。没出现 `LLM API_KEY 未配置` / `LLM HTTP ...` / `无法从返回内容解析出 JSON` 这类具体信息就不用动代码。
- **测试返回 `{"ok":false,"hint":"无 action…"}`**：说明用的是默认测试模板（没带 `action`），云函数故意不干活。改成 `{"action":"backfill"}` 或 `{"action":"gen",...}` 再跑。
- **生成的回看内容「很干 / 不像复盘」**：那是提示词效果问题，删掉 `analysis` 里对应的旧文档再重跑（按 `openid + type + start` 幂等，不删旧的会跳过）。
- **出「LLM HTTP 4xx / 401」**：密钥没配或失效，去「云函数 → 配置 → 环境变量」核对 `LLM_API_KEY`；**超时 3s** 也要在这里把执行超时改成 60s。

## 个人画像

在「回看」页顶部有一张 **个人画像** 入口卡（已生成才显示），点进去是一份基于你**全部历史记录**生成的「专属人物深度分析报告」，按固定七章结构呈现：

1. **基础人物画像**：客观基础信息 / 能量模式（充电与耗电场景，标高低消耗）/ 决策模式（倾向、固有漏洞、思维陷阱）/ 身体约束 / 财务现状与底线顾虑 / 环境与社交偏好（能接受什么、绝对排斥什么）
2. **核心盘点**：优势（写明何时发挥价值、何时失效）/ 短板（写明触发条件与后果）/ 内在矛盾（拆到两边各是什么诉求 + 典型爆发场景，不只罗列标题）
3. **适配方向推荐**：分【优先尝试 / 谨慎尝试 / 尽量避开】三档，另附风险清单（每条写「触发条件 → 连锁后果 → 预警信号」）与生活习惯 / 自我调节方案（具体动作 + 何时执行）
4. **未来图景推演**：中性 / 乐观 / 保守风险 三种情景，每种都先写**触发条件**再推演（条件推演，非预言）；乐观情景要点明「必须做到哪几件关键动作」以及伴随的新代价
5. **实操行动方案**：低成本试错行动（做什么 / 多久一次 / 耗时 / 判断标准 / 止损条件）/ 长期规则与个人边界红线（含何时启动边界保护）/ 复盘监测指标（要求可观察可量化，并写明复盘频率）
6. **决策辅助专项**（针对反复思虑）：适合一次性拍板还是分阶段小步验证 / 推荐的思考框架与要避开的思维陷阱 / 试错策略（哪些可大胆试、哪些绝不能试）
7. **总结**：一句话核心课题 + 当下最高优先级的 1~2 件事

硬性规则（写在提示词里）：只基于你的记录、不脑补虚构；每条【推论】都要能对应至少 1 条具体事实，禁止套通用人格模板；禁止空洞鸡汤与空泛心理学套话；**每一条建议都要写明适用场景、执行成本、潜在副作用、判断标准**；重点挖「本能行为陷阱」（下意识自动发生、事后反复纠结内耗的习惯）；不美化、不安慰式话术；资料里没信号的那一节宁可留空数组，不硬凑。

它不是某段时间的复盘，而是跨全部记录「你大概是哪种人、适合往哪走、容易卡在哪、怎么决策」的轮廓。

**生成与刷新**

- 进「个人画像」页，若还没生成，点 **生成个人画像**（或下拉）会调云函数 `action:'profile'`：取你全部记录（最多 500 条）→ 大模型生成 → 存 `profile` 集合（每 openid 一份，再次生成会覆盖更新）。
- `profile` 是**按需生成**，不在每晚定时任务里跑（避免和日 / 周 / 月 / 年回看争60s 额度）。每 openid 只保留最新一份。
- 交互上有三个刻意设计：
  - **下拉刷新 = 只重新读取**已有画像（`profileGet`，秒回、不花大模型额度），不会重新生成。
  - **重新生成 = 真调大模型重算，每个自然周只能点一次**（周一 00:00 按中国时区重置——不是滚动 7×24h，所以周一零点后立刻可再生成；判定用「上次生成是否落在当前这一周内」。**云函数 `generateProfile` 里才是真正的拦截**（判定在云端，直接返回 `cooling` 不调大模型），前端 `applyCooldown` 只负责把按钮置灰、少发无谓请求；控制台可传 `force:true` 绕过，仅供排查）。
  - **生成是后台任务**——点一下立即提交，页面进入「正在生成，请稍后查看」状态并自动轮询，出结果后自动渲染 + toast 提醒，你可以先离开页面再回来。
- 首次生成（还没有画像）不受冷却限制，随时可生成。
- 回看页顶部那张入口卡显示画像的 `summary` 一句话；完整报告在「个人画像」页里。**改了提示词结构后，旧的画像文档字段对不上新版，请重新点一次「生成个人画像」。**

**控制台手动测试**（控制台「云端测试」不带身份，需自己带 openid，从 `records` 集合任意文档的 `_openid` 字段复制）：

```json
{ "action": "profile", "openid": "你的openid" }
```

只读已存的用 `{"action":"profileGet","openid":"你的openid"}`。同样要先把 `analysis` 云函数「上传并部署（云端安装依赖）」，并等 1~2 分钟避开实例重建的瞬时 `ret=-3`。
